Gerador de Currículo Inteligente

Sistema próprio de automação para geração de currículos personalizados em PDF a partir da descrição de vagas.

Resumo executivo do projeto

O Gerador de Currículo Inteligente é uma aplicação criada para resolver um problema real e recorrente do processo de candidatura: adaptar o currículo para cada vaga sem perder consistência, credibilidade e qualidade visual. O sistema permite colar a descrição da vaga em uma interface web local, informar cargo e empresa, e gerar automaticamente um currículo em PDF alinhado ao contexto da oportunidade. O projeto usa uma base mestre de carreira em Markdown como fonte de verdade, templates HTML/CSS para padronização visual, Codex CLI como motor de geração assistida por IA, pipeline Python para orquestração, navegador headless para exportação PDF e uma UI Flask para tornar o fluxo simples e repetível.

O projeto começou como uma automação local baseada em arquivos e evoluiu para uma ferramenta com interface web, geração de PDFs em uma página, salvamento estruturado das vagas, controle de outputs, identidade visual própria, documentação técnica e preparação para deploy privado em ambiente Linux, mantendo compatibilidade com o uso local por scripts `.bat`.

Problema de negócio resolvido

O processo manual de adaptar currículos para vagas diferentes costuma ser lento, repetitivo e sujeito a inconsistências. O projeto resolve esse gargalo criando um fluxo padronizado em que a descrição da vaga é usada como filtro de relevância para selecionar experiências, projetos, tecnologias e bullets mais aderentes, sem alterar a base mestre da carreira.

O sistema reduz o tempo de preparação de currículos personalizados, melhora a consistência entre versões, mantém rastreabilidade das vagas usadas como entrada e entrega um PDF final pronto para envio. Também permite preservar o histórico de vagas em `legacy/` e outputs finais em `output/`, criando uma trilha operacional simples para revisar, comparar e reutilizar versões.

Arquitetura geral

O projeto foi organizado em camadas simples, preservando a pipeline original e adicionando uma camada de UI sem reescrever a lógica principal.

Camada de entrada local e web

`ui/app.py` contém a aplicação Flask, as rotas principais e a integração com o serviço de geração.

Rotas principais:

`GET /` renderiza a interface web.

`POST /generate` recebe cargo, empresa e descrição da vaga em JSON.

`GET /output/<filename>` serve apenas arquivos PDF gerados dentro de `output/`.

A rota de output possui proteção contra path traversal, resolve o caminho solicitado, garante que o arquivo esteja dentro de `output/` e permite apenas extensão `.pdf`.

Camada de serviço da UI

`generator/ui_service.py` funciona como camada intermediária entre Flask e a pipeline antiga. Essa camada:

normaliza nomes de arquivos

remove caracteres inválidos para Windows

gera slug da vaga

salva a descrição em `legacy/`

cria nomes únicos para evitar sobrescrita

define o nome final do PDF

executa `gerador_de_cv.py` por subprocess

valida se o PDF final foi criado

retorna caminho da vaga, caminho do PDF, nome do PDF e stdout da execução

Camada CLI principal

`gerador_de_cv.py` é um entrypoint fino que delega para `generator.pipeline.main()`.

Essa decisão preserva compatibilidade com o fluxo antigo, com os `.bat` e com execuções manuais via terminal.

Camada de pipeline

`generator/pipeline.py` concentra a orquestração principal:

resolução dos caminhos do projeto

leitura de `career/career_master.md`

leitura opcional de `career/raw_notes.md`

leitura dos templates HTML/CSS

leitura das personas de headhunter

localização de vagas em `jobs/`, raiz e `legacy/`

montagem do prompt final

chamada ao Codex CLI em modo não interativo

sanitização do HTML retornado

aplicação do modo compacto de uma página

salvamento do HTML intermediário

exportação para PDF via navegador headless

remoção do HTML intermediário quando `--pdf-only` está ativo

anexo opcional de portfolio visual via pypdf

Camada de IO

`generator/io_utils.py` concentra funções utilitárias para leitura de texto, busca de arquivos de vaga, localização da vaga mais recente, criação de diretórios e inline de CSS no template HTML.

Fluxo técnico completo

1. O usuário abre a interface local pelo `.bat` ou acessa a aplicação web.

2. A UI exibe um formulário com cargo, empresa e descrição da vaga.

3. Ao clicar em gerar, o frontend envia um `POST /generate`.

4. O Flask valida a descrição e chama `generate_resume_from_description()`.

5. O serviço salva a vaga como arquivo Markdown em `legacy/`.

6. O serviço monta um comando Python chamando:

`python gerador_de_cv.py --job <vaga> --one-page --pdf-only --no-portfolio --output-name <arquivo.pdf>`

7. A pipeline carrega a base mestre de carreira, templates, personas e vaga alvo.

8. O prompt é montado com regras de ATS, fidelidade aos fatos, idioma da vaga e modo de uma página.

9. O Codex CLI é chamado por subprocess em modo não interativo.

10. A resposta final do Codex é tratada como HTML.

11. O HTML é sanitizado para remover fences de Markdown, corrigir `**bold**`, normalizar contato do WhatsApp e remover frases proibidas.

12. O modo `one-page` injeta CSS compacto para caber em uma página A4.

13. O HTML é salvo temporariamente em `output/`.

14. O navegador headless exporta o HTML para PDF.

15. Com `--pdf-only`, o HTML intermediário é removido.

16. A UI exibe estado de sucesso com nome do arquivo, caminho local e botão para abrir o PDF.

Riscos técnicos identificados

A pipeline depende do Codex CLI instalado, disponível e autenticado.

A geração pode demorar, pois envolve chamada a modelo e exportação PDF.

A exportação PDF depende de Chrome/Edge/Chromium headless.

Em deploy Linux, a plataforma precisa permitir instalação ou presença de Chromium.

Em plataformas com filesystem efêmero, arquivos em `legacy/` e `output/` podem sumir após restart.

O uso de subprocess exige cuidado com validação de caminhos e nomes de arquivos.

O token de proteção é uma barreira mínima, não um sistema completo de usuários.

O app deve ser usado em deploy privado, preferencialmente com HTTPS.

PDFs gerados podem conter informações pessoais e não devem ser públicos.

## RadioFlow Esperança FM — Sistema de Gestão de Contratos e Cobranças

Resumo executivo do projeto

RadioFlow Esperança FM é um sistema web operacional para gestão comercial e financeira de uma rádio, criado para substituir controles manuais, planilhas antigas e dependência de atualização manual por outro setor. O cliente enfrentava um problema real de perda de prazos de vencimento, esquecimento de cobranças e baixa rastreabilidade sobre contratos, parcelas e acordos comerciais. O sistema centraliza clientes, pacotes comerciais, contratos, parcelas, vencimentos, relatórios, histórico, geração automática de contratos e cobranças manuais via WhatsApp. O projeto evoluiu de um MVP visual para uma aplicação Next.js com arquitetura por domínio, integração real com Supabase, migrations SQL versionadas, regras de acesso por perfil, RPCs transacionais, RLS e testes automatizados cobrindo fluxos críticos.

Problema de negócio resolvido

A operação comercial da rádio dependia de uma planilha antiga, alimentada manualmente por outro setor. Isso gerava atraso na atualização das informações, ruído entre áreas, perda de prazos de vencimento e risco de esquecer cobranças. Além disso, os contratos não seguiam sempre um padrão simples: alguns clientes pagavam mensalmente em uma data fixa, outros pagavam duas vezes no mês, outros tinham valores diferentes por parcela, acordos específicos, renegociações e particularidades comerciais negociadas caso a caso.

O RadioFlow organiza esse processo em uma plataforma única, reduzindo retrabalho, melhorando rastreabilidade financeira e dando mais clareza para acompanhar contratos ativos, parcelas pendentes, pagamentos registrados, clientes inadimplentes, clientes vencendo hoje, clientes vencidos e prioridades de cobrança. A solução também melhora a comunicação operacional, porque deixa o histórico e as regras de cada contrato mais acessíveis para quem precisa cobrar, acompanhar ou renegociar.

Decisões de arquitetura

O projeto adota Next.js App Router como base de aplicação, com src/app concentrando rotas, layouts e API routes. As telas ficam em src/features, os componentes reutilizáveis em src/components, as regras auxiliares em src/lib, a integração com Supabase e regras server-side em src/services, e as entidades centrais em src/types.

As operações mais sensíveis foram deslocadas para o backend e para o banco. Contratos são criados e editados por RPCs no PostgreSQL, não por atualizações soltas no client. A edição de contratos exige motivo, preserva parcelas pagas e registra alterações. A cobrança via WhatsApp é propositalmente manual: o sistema prepara a mensagem, registra o log e só então abre o link wa.me, mantendo a ação final sob controle humano.

Impacto para o negócio

O RadioFlow transforma um processo comercial manual, frágil e dependente de planilha em uma operação mais rastreável, organizada e auditável. A rádio passa a ter uma visão mais clara de clientes, contratos, vencimentos, pagamentos, inadimplência, prioridades de cobrança e acordos específicos. O sistema reduz esquecimento de cobranças, melhora o controle financeiro, diminui risco de perda de informação e profissionaliza a rotina de acompanhamento sem tirar o controle humano da operação.

O impacto principal foi dar previsibilidade para uma rotina que antes dependia de memória, planilha e comunicação entre setores. Com clientes, contratos, parcelas, vencimentos, histórico e mensagens de cobrança centralizados, o operador consegue identificar o que está vencido, o que vence no dia, o que já foi pago e quais contratos exigem atenção. Isso melhora tanto a cobrança quanto a tomada de decisão comercial.
